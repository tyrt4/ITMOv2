## Overview (Spec Kit)

### Видение
Ветка Spec Kit формализует тот же продукт (витрина кофейни) через артефакты spec → plan → tasks для backend и frontend. Цель — отделить «что и почему» (spec) от «как» (plan) и обеспечить прозрачные гейты (review) между фазами.

### Аудитория
- Студенты и разработчики, практикующие SDD в стиле Spec Kit
- Ревьюеры/менторы, проверяющие соответствие конституции и гейтам

### Ключевые сценарии
- Просмотр меню и деталей (ingredients, calories, prices)
- Создание заказа и оплата (mock)
- Просмотр скидок (daily / happy hour) и статуса магазина
- Чтение/публикация новостей (Admin)
- Начисление баллов лояльности, добавление отзывов

### Scope итерации
- Входит: in-memory данные, публичные `/api/*`, админские `/api/v1/*`, UI как статическая витрина
- Не входит: персистентность БД, аутентификация, внешние платежи

### Карта артефактов
- constitution.md — стандарты стеков/тестов/ограничений
- backend/spec.md — пользовательские истории, функциональные требования, AC
- backend/plan.md — стек/архитектура/эндпоинты/тесты/риски
- backend/tasks.md — фазы и критерии done
- frontend/spec.md — страницы, сценарии, AC и состояния
- frontend/plan.md — стек/компоненты/интеграция/доступность
- frontend/tasks.md — задачи по страницам/компонентам
